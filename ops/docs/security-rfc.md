# 天梯凭据安全与兼容迁移 RFC

状态：提案，未批准实施。归属 P1-01/P1-03；矩阵与上线状态仍归 [validation.md](validation.md)。
本 RFC 不改变当前 `昵称$密码`、明文 pass 比较、数据库或客户端协议，不读取旧账号/密码。

## 已确认的边界

`plugins/ladder-core/index.js:118–144` 直接比较 user.pass 与输入、创建时保存密码值。
网页 HTTPS/WSS 不等于原生 TCP 的加密通道。客户端本地完整登录串及现有日志也需分别评估。
本轮三个锁文件的 npm 安装审计报告了漏洞；保留审计结果，按可达路径/影响分类，不直接 force 升级旧栈。

## 拟议方案与授权前的审查

- 服务端采用版本化密码摘要，候选为 Argon2id；参数先以目标主机、并发登录、内存限额和抗 DoS 测试确定。
  每账号独立盐与算法/参数记录，不可直接把现有密码当哈希；pepper 如采用须有独立密钥交接和恢复方案。
  [Argon2 规范 RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html)
- 用户成功登录且旧值验证通过时，事务内写新摘要并清除旧值；后台离线转换、兼容窗口和空密码账号策略须另外批准。
  不通过迁服或 schema init 偷做转换，不改变既有昵称/密码分隔、旧客户端参数及比赛结算。
- 登录版本识别、并发登录竞态、错误密码、速率限制与日志脱敏需要针对性回归。公开 API 全程 HTTPS；
  原生 TCP 的 TLS/受控隧道或客户端升级是独立方案，不能宣称密码哈希保护了网络上的明文。
- schema 变更提供显式迁移和隔离恢复测试，生产 synchronize 保持 false。迁移前备份、窗口、owner/runtime 权限明确。
- 回退不能恢复旧明文作为日常运行方式；旧程序不认识新摘要时应保持维护、恢复兼容代码或经过批准的私有批次。
  不把新摘要当旧密码比较；需要选定前向兼容/撤回策略后才能实施。

需要维护者决定：威胁边界、参数预算、迁移窗口、旧客户端支持、传输方案、恢复策略与风险接受者。
仅阅读此 RFC、CI 或 unit test 通过都不能填 securityReviewAccepted；发布 gate 需要明确的人工作业记录。
