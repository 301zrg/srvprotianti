# 天梯月报、Discord 查询与 X 发布素材设计

状态：实现完成，Windows 本地验证通过；用户已要求正式部署，月报频道已创建、202609 已补发、自动推送已开启。确认/实现日期：2026-10-11。
本文维护独立服务侧的月报方案；代码完成、本地验证、Discord 验收和正式部署分别记录。
本文的 `/meta`、月报调度和素材导出已在当前 PC 部署；真实 macOS 验收仍需在迁移时完成。

## 1. 已确认的行为与范围

- Discord 提供上月及指定月份的公开天梯数据查询，默认查询上月。
- 卡组取使用率 Top 15，展示使用率、对全部对手的总体 Match 胜率，以及这 15 类彼此的对阵胜率。
- 主卡怪兽、主卡魔法、主卡陷阱、额外、副卡各取使用率 Top 10。
- 完整月报共四张 PNG，Discord 和 X 使用同一份月报数据。
- Discord 使用独立月报频道，建议名 `#monthly-meta`；每月 1 日北京时间 10:00 自动发布上月报告。
- X 面向国际 1103 玩家，英语为主、兼顾日语。第一版生成文案和图片，由用户免费手动发推。
- 月报和导出推文附所选月份的 `usage-stats.html` 链接，明确使用英语参数 `L=en`。

本轮不新增 X 自动发布服务、账号授权或付费 API 配置。卡组对所有细分类的完整矩阵、
独立胜率排行榜、先后攻及主/备牌单局矩阵不进入四图月报；完整数据通过现有网页查看。
QQ 不增加月报命令或推送，共享代码改动需保持 QQ 现有功能。

## 2. 当前实现与模块边界

当前公开接口已经具备所需月份、细分类和对阵数据，无需改游戏宿主、schema 或统计公式。
参数、响应及分母的权威定义见 [公开 API 与统计契约](../../docs/WEB_AND_ANALYTICS_SPEC.md)。

| 职责 | 入口 |
| --- | --- |
| 公开 API 请求、超时与响应校验 | `src/api.mjs` |
| 月份规范化、报告模型、缓存、素材归档与 ZIP | `src/monthly-report.mjs`、`src/monthly-report-zip.mjs` |
| 四图渲染与可移植字体 | `src/monthly-report-render.mjs`、`src/assets/fonts/` |
| 定时、每频道投递状态与恢复 | `src/monthly-report-scheduler.mjs` |
| 文案、链接和命令业务 | `src/monthly-report-text.mjs`、`src/i18n.mjs`、`src/service.mjs` |
| 配置与生命周期 | `src/config.mjs`、`src/runtime.mjs` |
| Discord 命令、附件、频道权限及消息恢复 | `../discord-bot/src/discord.mjs` |
| 可独立运行的部署包 | `../bot-tools/build-release.mjs` |

Bot 只调用公开 HTTP API，不连接游戏数据库，不读取插件内部文件，也不持有玩家密码。
共享模块输出数据和附件，Discord 适配器承担平台 I/O。仍沿用 ESM、Node.js 20+ 和现有 `sharp`。
现有 `MonthlyScheduler` 实际是每天 04:00 的当月玩家 Top 10 播报，继续保持原语义；
新月报使用独立调度器及状态文件，不能把旧 `lastAttempt` 当作每月投递记录。

## 3. 报告数据与统计展示

### 3.1 获取顺序

1. 取得所选月的卡组使用率，排除 4095“其他”后，按接口现有顺序取前 15 类。
   不足 15 类时展示实际数量，不补零样本卡组，不重新归并分类。
2. 按这些 `deckTypeId` 请求细分类详情，读取 `overall` 和 `opponents[].values` 的 Match 数据。
   每行只按对手 ID 选择对应列；全部对手的总体胜率直接读取 `overall`。
3. 取得五种区域的卡片前 10 项。完整四图需要英日名称，分别使用 API 的 `lang=en|ja`，
   按 `cardId` 合并名称；排名、计数和率来自同一有效响应，并校验两种语言的计数一致。
4. 全部请求成功且通过校验后建立报告模型，再生成四图、摘要和推文素材。

完整报告正常需要一次卡组使用率、最多 15 次详情、五区域各两次卡片查询，共最多 26 次请求。
共用队列最多同时发出 2 个游戏 API 请求；同月份并发生成合并为一个任务。
只取所需卡片第一页，不扫描历史卡组快照，不新增游戏侧批量接口。
单项卡片查询只取该区域和所需语言；后续可复用已生成模型中的数据。

### 3.2 模型与校验

报告模型至少保存 `schemaVersion`、`month`、`generatedAt`、`coverage`、所选分类及名称、
各行使用计数/率、总体胜数/分母、每个有方向对阵的胜数/分母、五类卡片计数/率/名称和网页链接。
原始率与整数计数保留完整精度，展示统一保留两位小数；导出 JSON 保留分子、分母。

- 响应月份必须与请求一致，防止接口把非法月份回退为当前月。
- ID 唯一，计数为非负安全整数，胜数不超过分母，比例为有限值且在 0–1 内。
- `validCardDecks <= allDecks`；卡片计数不超过有效样本，卡组计数不超过全部样本。
- 各使用率响应的覆盖计数、同 ID 的使用计数必须一致；不一致时短暂重试整个数据批次一次，
  仍不一致则报告暂不可用，不拼接相互矛盾的数据。
- 对阵缺项在响应整体有效的前提下表示零样本；请求失败不等于零样本。
  总体胜率不通过相加矩阵中的 15 列重算，也不由反向格推算当前格。

上述 API 请求不构成数据库事务快照。报告记录生成时间与来源；历史回填、重分类或修复后，
网页及新查询可能与已发布报告不同。普通发布不触发回填，不修改已发布素材。

### 3.3 读者需要看到的口径

- 使用样本是 Match 中参赛卡组的使用次数，不是独立卡组、玩家人数或物理 Match 场数。
- 卡组使用率、卡片使用率和胜率分别沿用提供者的分母，不能互相替换。
  每行显示使用次数和总体胜率样本数，每格显示胜率及其样本数。
- “其他”的占比单独列在图注，不参与 Top 15 名次，但继续留在使用率分母中。
  同时列 Top 15、其余已识别类型、其他的使用占比，避免误以为 Top 15 覆盖全部使用。
- 卡片覆盖率显示为 `validCardDecks / allDecks` 和百分比；副卡是 G1 初始副卡配置，
  不描述成实际换入频率。不同卡片的使用率不构成相加为 100% 的份额图。
- 矩阵行是己方，列是对手；有样本的同类对阵按接口显示总体 50%，无样本显示 `—`。
- 非零小样本仍展示真实胜率和 `n`。设计默认 `n < 20` 加 `*` 并减弱底色，图注明确其为
  小样本提示而非显著性检验；不把一场获胜的 100% 染成强优势。零分母始终为 `—`。

## 4. 四张图片与语言

| 顺序与文件名 | 内容 |
| --- | --- |
| `01-decks-YYYYMM.png` | 同一张图合并 Top 15 使用率、对全部对手的总体 Match 胜率和 15×15 对阵矩阵 |
| `02-monsters-YYYYMM.png` | 主卡怪兽 Top 10 |
| `03-spells-traps-YYYYMM.png` | 主卡魔法 Top 10、主卡陷阱 Top 10，各一个栏 |
| `04-extra-side-YYYYMM.png` | 额外 Top 10、副卡 Top 10，各一个栏 |

第一张采用较宽画布，左侧按使用率排名列编号、英日卡组名称、使用次数/率、总体胜率/样本，
右侧列头用相同编号标识 15 个对手。每格两行显示胜率和 `n`，避免重复长列名挤压矩阵。
图中注明 `Row deck vs column deck`、总体包含全部对手，以及点击原图放大查看的提示。
矩阵是需要放大阅读的详细图，不承诺在 X 四图缩略图或手机聊天缩略图中直接读清每格。

先以约 2880×1920 的矩阵图和约 1600×1800 的卡片图验证排版，尺寸可为阅读体验调整。
卡片图以英日名称、排名、使用率和使用次数为主；1/2/3 张投入分布留在网页。
每图包含项目名称、月份、生成时间、统计范围和必要图注；不加入玩家名单或私有数据。
不截取网页 DOM，也不通过图像生成模型绘制数字。

完整报告的图表标题以英语为主，日语作简短补充，名称使用 API 提供的英日文本。
卡名缺失时保留提供者回退值，不现场翻译成新的卡名。
Discord 主动月报使用英、日、韩、中四语言短说明，每种语言一句，明确列出主卡怪兽、主卡魔法、
主卡陷阱、额外、副卡五种区域；月份标题、四张图片和英语月份链接各提供一份。
统计数字和完整榜单由共用图片承载，不在四语言正文中逐项重复。
详细口径、小样本说明和查询帮助放在频道置顶说明中；图片保留必要图注。
命令正文按用户 locale，允许显式选择四语言。卡组查询正文提供所选语言的 Top 15 名称和编号，
方便与共用矩阵对照；单项卡片查询提供该语言卡名。
单项卡片查询图可以按所选语言渲染，完整四图保持同一英日发布版。

主动月报正文模板（202609 已用于正式频道补发）：

```text
2026-09 · OCG 1103 Nexus Monthly Report

EN · Top 15 decks by usage with overall and matchup Match win rates; card usage Top 10 for Main Deck monsters, Main Deck spells, Main Deck traps, Extra Deck and Side Deck.
日本語 · デッキ使用率上位15種の総合・対戦別マッチ勝率と、メインデッキのモンスター・魔法・罠、エクストラデッキ、サイドデッキ各部門のカード採用率上位10枚。
한국어 · 덱 사용률 상위 15종의 전체 및 상대 덱별 매치 승률과 메인 덱 몬스터·마법·함정, 엑스트라 덱, 사이드 덱 각 부문의 카드 채용률 상위 10장.
中文 · 卡组使用率前15及总体、对阵 Match 胜率；主卡怪兽、主卡魔法、主卡陷阱、额外、副卡使用率各前10。

Full data / 詳細 / 전체 통계 / 完整数据：<英语月份链接>
```

月份和链接按报告替换，数据不足时按实际数量提示；四种说明按普通文本生成。
生成后的完整正文做平台长度检查，不能为了放下四语言而省略五种区域名称。
正式推送与预览正文均不展示 X 素材导出命令；素材仍通过 `/meta view:export` 按需私密下载。

字体必须随部署包携带可分发的必要字体及许可证，渲染时显式加载，避免依赖 Windows 系统字体。
包构建器当前按 UTF-8 复制平面源码，需要增加字体等二进制资源的明确复制步骤，
并保留现有拒绝覆盖运行文件、符号链接/目录联接及目录越界的保护。
Windows 本地、macOS（含拟迁入的 Mac mini）和 Linux 部署包均需检查日语/中文回退字符、
长名称、换行和数字不截断；尚未在目标机器验收时不能记为跨平台通过。
每张 PNG 目标控制在 4 MB 内，压缩后仍检查字体清晰度；最终发送按实际平台附件预算校验。

## 5. 月份链接与命令

### 5.1 网页链接

所有报告都生成：

```text
<公开网页根目录>/usage-stats.html?period=month&month=YYYYMM&metric=deck&L=en
```

例如 2026 年 9 月：[英语使用率页面](http://121.4.34.71:7922/usage-stats.html?period=month&month=202609&metric=deck&L=en)。
选择 `metric=deck` 方便从卡组榜点击进入同月详情，其余区域在页内切换。
语言参数是页面的 `L=en`，不是卡片 API 的 `lang=en`。

公开网页基地址优先取月报配置，缺省时从现有 `guide.introUrl` 的所在目录派生。
不能直接使用可能指向本机或内网的 `gameApi.baseUrl`。通过 `URL` 构造路径和参数，
保留固定部署子路径，清除不相关 query/hash；不接受用户输入任意网址。
Discord、四图文字版和 X 文案都使用同一个英语月份链接，不随 Discord 用户 locale 改变。
原使用率页面已经识别上述参数，本轮不修改网页。

### 5.2 `/meta` 设计

| 用法 | 行为 |
| --- | --- |
| `/meta` | 返回上月四图、所选语言短摘要和英语月份链接 |
| `/meta month:2026-09` | 返回指定月四图 |
| `/meta view:decks` | 返回所选月卡组汇总、所选语言名称/编号及共用对阵矩阵图 |
| `/meta view:monster\|spell\|trap\|extra\|side` | 返回对应区域 Top 10 的可复制文字和单项图 |
| `/meta view:export` | 仅服务器所有者或拥有 Administrator 权限的管理员；私密回复所选月的 X 发布素材包，优先导出该月已发布批次 |
| `/meta view:preview` | 仅服务器所有者或拥有 Administrator 权限的管理员；在现有命令频道发送正式四语正文加四图，不修改自动投递状态 |
| 上述命令加 `language:English\|日本語\|中文\|한국어` | 覆盖 Discord locale 对正文/单项查询图的语言选择 |

`month` 接受 `YYYY-MM` 或 `YYYYMM`，内部规范化为 `YYYYMM`；严格校验自然月份和年份，
拒绝未来月份，不交由服务器静默回退。默认上月使用 `Asia/Shanghai` 计算，正确处理跨年。
允许查询当前月，但明确标为“进行中数据”；定时发布只取已结束的上月。
历史月无数据时回复明确空状态和月份链接，不填充别月数据。

命令沿用已配置 `commands: true` 的频道和 guild 检查，不在月报频道开放随意查询。
`view` 改用动态候选列表，普通成员仅见七种公开查询，`export`、`preview` 仅向服务器所有者或
拥有 Administrator 权限的管理员返回。仅有“管理服务器”权限不满足条件。执行时复用同一权限判断，
手动输入隐藏选项、使用旧客户端候选或提交未知值均在查询/公开回复前拒绝，错误仅本人可见。
动态候选不调用统计 API。自动补全允许用户提交候选以外的文本，因此另做值白名单校验；机制见
[Discord Application Commands](https://docs.discord.com/developers/interactions/application-commands#autocomplete)。
图片生成前先 defer 回复。完整报告先发一条短摘要加四图；长榜单或附件超限时按平台预算拆分，
正文和附件错误使用请求语言反馈，不出现成功摘要搭配不完整四图。
`export` 使用私密交互回复，不主动发送私信，不向频道发送本机文件路径。
普通查询与导出不修改自动投递状态，也不会触发主动月报或发推。

## 6. 免费手动发推素材

每份完整报告生成同一版本的四张 PNG、`x-caption.txt`、四图的替代文本说明、
`report-data.json` 和含主要数字的 `report-summary.txt`，可下载为 ZIP。
文案以英语为主，增加一句日语月报说明、英语月份链接；通过官方字符计数规则检查
不超过 280 个加权字符。文案写实际月份，不写会随阅读时间改变的“上个月”。
ZIP 超过交互附件预算时改为私密回复分别提供图片和文本素材。
用户在 X 选择四图、粘贴文案并发布；程序不登录 X，也不标记已经替用户发推。
内容、生成时间和文件名明确对应同一报告批次。

### 6.1 保存位置与远程下载

持久副本放在机器人实际运行机器的服务目录内，不固定到本次开发机的盘符或用户目录。
所有相对路径基于服务根目录解析，不基于启动命令的当前工作目录。例如：

```text
<Discord Bot 运行目录>/
  data/
    monthly-report-state.json
    monthly-reports/
      202609/
        <报告批次>/
          01-decks-202609.png
          02-monsters-202609.png
          03-spells-traps-202609.png
          04-extra-side-202609.png
          x-caption.txt
          x-alt-text.txt
          report-data.json
          report-summary.txt
          manifest.json
```

ZIP 按这一批次的文件清单生成，下载名为 `ocg1103-meta-202609.zip`，可按需打包，
不把已发布素材重新取 API 并覆盖成另一个版本。
`/meta view:export month:2026-09` 默认找到该月已发布批次；没有发布记录时，
才使用有效的查询批次或新生成一份，并在回复中说明生成时间及是否为已发布版。
普通 `/meta` 查询仍可取得当前缓存/API 的最新数据，两种用途的版本差异要明确标注。

素材下载通过 Discord 交互附件返回，回复仅执行命令的人可见。
用户可在自己的电脑上下载、解压和发推，不需要登录机器人运行机器或共享它的文件夹。
主动月报的一条消息附四图、英语月份链接和一行导出命令提示；不为 ZIP 额外刷一条群消息。
Discord 是下载入口，运行目录里的素材是保留历史批次和重建下载包的持久来源。
第一版不引入网盘账号、公开文件服务或云存储凭据。

### 6.2 Mac mini 迁移与备份

未来迁入 Mac mini 时，部署步骤为：停止旧机器的 Discord Bot；复制独立部署包、
对应私有配置和整个 `data/` 到新运行目录；在 Mac mini 上重新安装锁定依赖并验证字体渲染；
核对公开 API、Discord 连接、频道权限与导出下载，再启动唯一活动实例。
不要跨系统复制 `node_modules`，也不要直接在 `services/releases/discord-bot` 构建目录里运行正式实例。

`data/` 同时携带历史月报素材和已发送状态，路径随运行目录迁移，不需要沿用 Windows 的绝对地址。
Discord 已发布消息继续用原消息 ID 关联；切换运行机器不重新发历史月报。
备份至少包含私有配置、所有状态文件和月报素材，备份位置按实际部署环境另行确定。
仅由 API 重新生成无法保证还原经过历史修复前的已发布素材，因此历史批次本身需要备份。

### 6.3 X 机制调研依据

截至 2026-10-11 查阅的官方资料：

- [字符规则](https://docs.x.com/fundamentals/counting-characters)：普通帖子采用 280 加权字符，CJK 通常权重 2，URL 固定权重 23。
- [创建帖子](https://docs.x.com/x-api/posts/create-post)：API 发帖先上传媒体，一条最多四张照片；免费手动方案仍采用四图布局。
- [计费](https://docs.x.com/x-api/getting-started/pricing)：官方 API 按量付费，文档标价普通创建 0.015 美元、带 URL 创建 0.20 美元/次；价格可能变化，不把这些数字作为免费发布承诺。
- [授权与刷新令牌](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code)：后续若增加自动发布，需独立设计用户授权和凭据生命周期。
- [自动化规则](https://help.x.com/en/rules-and-policies/x-automation)：自动广播有用信息允许，网页脚本自动发帖禁止。

后续自动发推需要重新确认届时的费用和授权，不在第一版搭建占位 X 服务或增加未使用凭据。

## 7. 定时、缓存、持久化与失败恢复

### 7.1 生成与保存

报告内存缓存默认 5 分钟，最多保存 3 个完整报告；图片缓存另设总字节上限，
避免连续查询不同月份或语言无限占用内存。同一键的生成失败不缓存为成功空报告。
游戏 API 请求与渲染分别限制并发，避免月报占用房间轮询、状态卡和连胜监控的执行队列。

发布素材的目录、下载及迁移规则见 6.1–6.2；写入时先写临时目录，再原子提交元数据。
批次包含数据摘要、算法/布局版本、生成时间、文件清单和内容哈希，四图必须全部就绪才可投递。
持久发布素材以月份和批次索引读取，文件名由程序固定生成，用户不能传入文件路径。
正常月报不覆盖已发布批次；命令缓存到期可以取得修复后的新数据，导出必须与本次回复批次匹配。
历史素材按需保留，不在第一版自动递归清理运行目录。

### 7.2 调度与去重

- 每月 1 日 10:00 `Asia/Shanghai` 到期；检查时依据到期时间比较，不能只匹配 10:00 那一分钟。
- 设计默认允许到期后 72 小时内恢复补发上月一次，适应个人电脑暂停/离线；
  超过窗口记录错过状态，仍可手动查询/导出，不回扫并补发所有历史月份。
- 目标来自显式 `monthlyReport: true` 的频道，按 `guildId:channelId:month` 独立记录。
  一处失败不让其他目标被视为已完成；同平台继续保持一个活动进程。
- 首次获取无数据时暂不发空月报，在补发窗口内延后检查；窗口结束仍为空则记录跳过。
- 发送前持久化 `sending` 及报告批次，明确成功后保存 `sent` 和消息 ID。
  不能复用当前会吞掉发送错误且无成功结果的 `proactive()` 来宣称可靠投递。
- 网络超时、5xx、进程中断可能已经发送成功，先核对月报频道中机器人自己的同月份消息及
  预期附件文件名；能确认成功则恢复 ID，能确认未发送才重试。权限不足或查找范围不足时
  保留待核对状态并记录原因，不盲目再发。稳定 nonce 只作为补充，不承诺跨月永久去重。
- 明确未接受的临时失败按退避重试，429 尊重平台等待时间；鉴权、权限和未知目标错误
  记录到对应目标，修复后继续核对/尝试。尝试受补发截止时间约束。

状态 JSON 原子写入，启动时校验；损坏文件不可静默重置并重发。
升级和换机保留新月报状态、发布素材及原有状态文件；缺失投递状态先核对目标频道历史。
API 获取或某张图渲染失败不发半份月报；日志记录月份、目标、阶段和脱敏错误，不记录凭据。

## 8. 配置与频道

下表配置已同步 Discord 默认模板及部署手册。对象沿用现有递归合并，频道数组整体替换。

| 配置 | 默认值与校验 |
| --- | --- |
| `monthlyReports.enabled` | `false`；只控制自动月报，查询/导出不依赖开启它 |
| `monthlyReports.timezone` | `Asia/Shanghai`，第一版只接受此值 |
| `monthlyReports.day/hour/minute` | `1/10/0`，第一版只接受已确认时点 |
| `monthlyReports.catchUpHours` | `72`，整数 0–168；0 表示只在到期的同一分钟尝试，不补发 |
| `monthlyReports.webBaseUrl` | 空字符串，回退到 `guide.introUrl` 所在目录；非空须是无账号凭据的 HTTP(S) 固定基地址 |

| `monthlyReports.artifactDir` | `data/monthly-reports`，必须位于当前服务目录内，不能是服务根目录 |
| `discord.guilds[].channels[].monthlyReport` | 缺省 `false`，若提供必须是布尔值 |

月报范围 15/10、完整报告英日图、链接 `L=en` 是本轮固定产品规则，不另造可变配置。

旧私有配置通过默认合并保持自动月报关闭，不自动把已有日榜频道选为月报目标。
QQ 运行时不启动新调度器，也不要求月报频道或新增 Discord 配置。

`#monthly-meta` 放在现有 PLAY 分类，成员可读，机器人和管理员可发帖；查询仍用命令频道。
机器人需要查看、发送、嵌入链接、附加文件和读取消息历史权限。
日常启动不创建、重命名或调整频道。当前频道已按用户要求一次性创建并核对成员可见性与附件权限，
实际 ID 和启用状态记录在 [Discord 部署手册](../discord-bot/DEPLOYMENT.md)。
对话没有选择群发提及，第一版使用 `allowedMentions: {parse: []}`。
