# 插件化重构开发流程与验收清单

## 1. 阶段顺序

### 阶段 A：基准恢复

- 以 `srvpro` 当前工作树逐项恢复 `srvprotianti` 的原项目核心行为。
- 恢复 `duel-finalization` 及其测试。
- 恢复原 `/api/getrooms` 和 `/api/replay` 鉴权。
- 消除 CoffeeScript/JavaScript 和 TypeScript/JavaScript 的源产物漂移。
- 保留现有未提交业务改动的语义记录，避免无意丢失。

### 阶段 B：通用插件宿主

- 实现 manifest、配置加载、依赖排序和生命周期。
- 实现数据库连接前实体注册。
- 实现随机模式、房间、单局、Match、HTTP 和静态页面通用钩子。
- 为无插件启动和故障插件隔离编写测试。

### 阶段 C：业务迁移

按依赖顺序迁移：

1. `postgres-compat`
2. `deck-classifier`
3. `ladder-core`
4. `ladder-analytics`
5. `ladder-usage-analytics`
6. `public-room-web`、`public-replay-web`（相互独立的基础 API）
7. `ladder-replay-enrichment`（组合公开录像与天梯卡组服务）
8. `ladder-web`

每迁移一项，就从主代码删除对应业务分支并验证空插件行为。

### 阶段 D：逻辑修复

- 修复无效卡组 JSON。
- 修复月榜历史查询。
- 修复单局胜者、先后攻和双镜像记录。
- 统一计分配置语义。
- 增加事务和幂等保护。
- 修复 API 隐私和输入边界。

### 阶段 E：数据迁移

- 先完成正式库只读审计。
- 输出 SQL/脚本、dry-run 报告和校验命令。
- 由维护者在正式服务器执行。
- 对无法可靠恢复的数据保留空值和报告，不猜测填充。

## 2. 每个改动的要求

- 先说明改动属于哪个插件或通用宿主能力。
- 不改动与任务无关的用户文件。
- 不修改 `config/admin_user.json` 和 `config/config.json`。
- 新增配置必须有默认值、字段说明和校验。
- 新增实体字段必须同步设计 migration 和回滚说明。
- 异步事件必须说明调用顺序、失败行为和是否影响主流程。
- 数据库操作必须说明事务边界和幂等键。
- 对非显然逻辑添加解释“为什么”的注释，而不是逐行翻译代码。

## 3. 必须执行的验证

### 空插件目录

- 服务能够启动。
- 普通房、随机房、观战、断线重连和录像行为与基准一致。
- `/api/getrooms` 与 `/api/replay` 保持原鉴权。
- 没有 TT 模式和天梯路由。
- 不注册天梯实体。

### 安装天梯插件

- 新用户和已有用户认证正确。
- 展示名称保留大小写，认证键不区分大小写。
- 同一 Match 只结算一次。
- 胜者加分、败者扣分，总/月数据一致。
- 断线重连不立即判负，新玩家不能占断线座位。
- 相同 IP 连续匹配默认允许，配置开启后才限制。
- 受限制玩家与正常玩家默认可匹配，配置开启后才分池。

### 单局与录像

- G1/G2/G3 的胜者、先后攻、卡组和 `duelCount` 正确。
- 每个实际单局产生两条镜像记录。
- `isMain` 与 `duelCount` 一致。
- 录像保存失败时积分、Match 和单局记录仍提交。
- 录像保存成功时可以正确关联 DuelLog。

### 卡组识别

- 模板主卡组和额外卡组都参与完整包含判断。
- 实战主卡组与额外卡组使用 `client.main` 合并区。
- 副卡组不参与。
- 部分重合不误判，回退为其他卡组。
- 重复卡数量的匹配语义通过测试固定。

### Web 与统计

- 页面只从插件 JSON 配置注册。
- 原管理接口鉴权不变。
- 新公开 API 无需管理员密码且防止路径穿越。
- 录像页展示小局和胜者，卡组下载名包含 `-gN-`。
- 总榜/月榜只显示一个等级分字段。
- 历史月份来自月记录。
- 不同卡组、同卡组、先攻、后攻、主牌和备牌统计有独立测试样本。

## 4. 编译和提交前检查

至少运行：

```text
npx tsc --noEmit --pretty false
npm run build
node duel-finalization.test.js
```

还应运行新增的插件单元测试和集成测试，并检查编译后没有出现源文件之外的意外大面积变化。

## 5. 历史问题隔离

重构提交不得顺手回填或删除正式数据。发现新问题时记录：

- 受影响表和字段。
- 开始和结束时间范围。
- 能否从其他表可靠恢复。
- 预估影响行数。
- 修复脚本依赖的代码版本和 schema 版本。

数据问题统一在插件结构稳定后处理。
