## 当前实现概况

项目在原 SRVPro 上提供可选 TT 天梯、账户计分、分类、排行/使用率、公开房间/录像与网页。
主程序保留通用协议、房间和插件扩展点；插件移除后仍应保持基础功能和原管理接口鉴权。

| 部分 | 实现及维护入口 |
| --- | --- |
| 主服务与宿主 | CoffeeScript 源码及生成 JS；通用 DataManager 使用 TypeScript。见 [宿主入口](../plugins/README.md) |
| 天梯与分类 | TT 认证/幂等事务结算、G1 分类冻结、双视角单局。见 [天梯](../plugins/ladder-core/README.md)、[分类](../plugins/deck_analysis/README.md) |
| 统计与页面 | 排行、玩家战绩、胜率、使用率、四语言卡片目录与八个页面。见 [模块导航](../AGENTS.md) |
| 公开录像 | 基础扫描/下载与天梯增强已分离；展示和筛选的具体数据来源见 [增强插件](../plugins/ladder-replay-enrichment/README.md) |
| QQ/Discord | [机器人](../services/community-bot/README.md) 独立进程，只消费公开 API。已有 QQ 联调和主动权限拒绝记录；不能等同于两平台完整验收 |
| 数据工具 | 历史修复、使用率建表/回填、模板重分类已有手册和工具；代码具备工具不代表生产已执行 |

依赖和运行命令以 manifest、各自 `package.json` 及模块文档为准。原交接记载主项目曾在
Node.js 24.15.0 下验证，该记录不是对任意版本或本次运行的保证。

## 上线前仍需核实的事项

以下来自既有交接，仓库内没有足以确认全部完成的生产验收记录。按实际环境逐项核实，
有新的日期、版本和验收证据后更新状态，不沿用旧快照行数。

1. **真实客户端终局与重连验收。** 终局队列排空、明确终局才结算、TT 双方超时不结算已有代码。
   仍需两客户端覆盖 G1/G2/G3、双方投降、`MSG_WIN type=0x04`、录像延迟/失败、
   子进程异常退出、先后重连及双方均不返回；同时验证普通房/随机房/观战与旧管理 API。
2. **生产历史修复与类型对齐。** 按 [历史修复手册](../plugins/ladder-core/migrations/202609-history-repair/README.md)
   在维护窗口备份、重新 audit/simulate/apply/verify。
   早期迁移库还需按手册判断是否执行 `05-align-game-decks.sql`，检查 `deck_type_mismatches=0`。
3. **旧错误胜者记录。** 代码修复只保证后续对局；旧记录需可靠逐局证据，
   并一致处理用户、月份、Match 与积分变化。不能从已知错误的单局字段反推真值。
4. **使用率生产准备。** 确认 [建表及运行角色授权](../migrations/202609-player-usage/README.md)
   和 [历史回填](../plugins/ladder-usage-analytics/BACKFILL.md) 已执行并验收。
   普通启动只处理新 Match；复制代码不会自动补齐旧月份统计。
5. **机器人平台验收。** 2026-09-23 已记录 QQ 联调以及无主动群消息权限的 `40034105`；
   需分别确认被动查询、具备权限后的主动推送及 Discord，不能写成“从未联调”或“两平台均已上线”。
   2026-09-26 Discord 联调确认 TUN 生效后 Node 可访问 Discord；随后鉴权接口返回 401，原因是
   把 64 位 Public Key 填入 `botToken`。配置校验已增加此类误填提示；正确值取 Developer Portal
   的 Bot → Token。凭据、目标群/频道及排查方法留在 [服务文档](../services/community-bot/README.md)。

## 已知限制与后续工作

- **录像/DuelLog 仍在结束流程的同步等待链中。** 结算不依赖保存成功，但保存时序尚未改成后台队列。
  优化前需设计可靠排队、幂等、重试和逐局对账，不能直接把 `await` 去掉。
- **大规模查询仍需实测。** 排行在 Node.js 中全榜编号；统计有短时进程缓存。
  数据量增长或多进程部署时再依据正式库执行计划与延迟评估优化，见
  [API/统计契约](WEB_AND_ANALYTICS_SPEC.md)。
- **录像分类的展示与筛选来源不同。** 当前展示从各录像玩家快照识别，筛选用已保存的 G1 类型；
  不能承诺两者始终一致。若要统一，需同时设计历史来源与接口兼容，本次未改变业务实现。
- **HTTPS、密码哈希与额外认证加固延期。** 原计划见 [部署草案](CADDY_HTTPS_DEPLOYMENT.md)；
  当前交接不授权安装代理、改防火墙或修改部署凭据。
- **云录像保持关闭。** 开启前需真实客户端跨脚本版本播放、内存压测、容量/保留期/清理/限流和损坏降级；
  不能承诺跨协议大版本兼容。
- **Challonge 保持关闭。** 恢复前单独核实 API 版本、套餐/调用额度并设计最终 Match 回写、重试与幂等。
  旧方案和额度估算仅在历史快照保留，不当作现行外部服务事实。
- **桌面客户端与 srvpro2 迁移为独立后续项目。** 见 [客户端调研](DESKTOP_CLIENT_RESEARCH.md)、
  [迁移调研](SRVPRO2_MIGRATION_RESEARCH.md)；机器人已经有实现，不再将三者混写为同一延期状态。

## 部署与维护边界

部署应以明确代码版本/差异生成清单，保留服务器本地配置与四语言 CDB；涉及源文件时同步生成 JS，
不要照搬旧交接某一批次的“只复制这些文件”。跨宿主版本使用完整版本包并遵守具体迁移手册。
机器人有独立依赖、测试与进程，不能随游戏服务复制插件就视为完成升级。
