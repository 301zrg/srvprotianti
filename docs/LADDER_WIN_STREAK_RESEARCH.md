> 更新：2026-10-09。状态：服务端连胜接口已上线，Discord `PLAY / #win-streaks` 已创建并启用；首条实际连胜消息由新达标比赛触发。
> QQ 独立服务已补齐相同连胜监控与主动群推送，待正式服务器部署及真实达标比赛验收。

## 确认的业务口径

- 连胜按已成功结算的整场 M / Match 计，胜者加一、败者归 0；跨月和重启保持。
- 进房战绩消息追加“当前 X 连胜中”；0 显示“当前暂无连胜”。切语言时同步更新文案。
- 首次启用时所有玩家从 0 开始，不读取或恢复历史连胜；上线后累计的次数跨月和重启保留。
- 不补播历史连胜。上线后达到 5 时开始播报，此后每次观察到新的获胜结果播报。
- 允许遗漏：Bot 错过 5～7 胜后恢复，只播短时间内的最新第 8 胜；过期不用补。
- 短时间窗口采用结算后 60 秒，默认每 5 秒检查；已输掉比赛的玩家不会返回旧连胜。
- QQ/Discord 每条连胜消息同时包含中文、英文、日文、韩文，附当前月等级分、胜场、胜负差和胜率。
- 不增加额外的“连胜终结”消息。

中文格式为：

> XX玩家当前X连胜！本月等级分XX、胜场XX、胜负差XX、胜率XX。

## 当前架构与实现

这是小到中等规模的跨模块扩展，无需改客户端或宿主游戏协议。

| 模块 | 实现 |
| --- | --- |
| [ladder-core](../plugins/ladder-core/README.md) | 用户表保存当前连胜和最近结算 Match 标记；与积分、胜负一起事务提交；进房提示使用插件翻译 |
| [ladder-analytics](../plugins/ladder-analytics/README.md) | 查询最近 60 秒内各玩家最新胜利，过滤至少 5 连胜，并关联当前月战绩 |
| [ladder-web](../plugins/ladder-web/README.md) | 提供只读 `GET /api/ladder/streaks`，不暴露对手、卡组或认证信息 |
| [bot-core](../services/bot-core/README.md) | 窗口轮询、最新结果合并、持久记录发送尝试；不建立历史补发队列 |
| [discord-bot](../services/discord-bot/README.md) | 独立频道开关、四语言文案、过期中止 REST 请求及稳定 nonce |
| [qq-bot](../services/qq-bot/README.md) | 独立群开关、沿用匹配提醒的主动权限、四语言文案及过期中止群消息请求 |

简化方案使用玩家当前状态，不新增 Match 连胜快照或专用消息队列。
每次检查完整的短时间窗口，不用最大 Match ID 作为消费游标，避免把自增 ID 分配顺序当成提交顺序。
原房间监控不承担胜负推断；Bot 仍是独立服务，离线不影响游戏统计。

发送前持久记录尝试，允许发送失败或崩溃时漏报，以减少重启重复。REST 请求在窗口结束时中止；
Discord nonce 仅辅助抑制短时间重复，不视为永久投递保证；QQ 使用同一持久发送尝试规则，没有额外 nonce 保证。
同一玩家两个轮询之间连赢多场只播最新一场，是本次明确接受的精度取舍。

## 从 0 初始化与上线

[连胜迁移手册](../plugins/ladder-core/migrations/202610-win-streaks/README.md) 提供加字段、验收和回退，
另保留可选的连接与字段预检。迁移给所有账户设置默认 0 连胜，无需审计或回填历史 Match。

迁移将所有旧账户的最近投递标记留空：历史上即使已有 8 连胜，启用后也从 0 开始，
首次新连赢 5 场才播报。迁移不修改原总/月积分、胜负或 Match。
生产保持 `synchronize=false`，先停服备份和迁移，再部署游戏代码及新 Bot。

详细字段归 [数据契约](DATA_MODEL_AND_MIGRATION.md)，公开响应归 [API 契约](WEB_AND_ANALYTICS_SPEC.md)。

## 频道选择

建议 PLAY 分类下单独建立 `#win-streaks`，成员可读、Bot 发言；频道 ID 通过
`winStreakAlerts` 配置，与匹配提醒和月榜开关独立。Bot 不在启动时创建频道。

专用频道便于独立关注/静音，持续 10 连胜会产生 5～10 共 6 条消息。
放到 `#matchmaking-alerts` 技术上同样可行，但会把等待邀战和赛后成绩混在一起。
希望减少频道数量时，可先放现有 `#ladder-stats`。
早期 Discord 施工记录曾记录匹配频道较多未读，这只是历史依据，不代表当前流量。
