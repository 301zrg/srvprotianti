# 宿主与模块架构规范

> 当前架构约束；文件名保留以兼容旧链接。一次性重构过程见
> [解耦实施历史](DECOUPLING_IMPLEMENTATION_PLAN.md)，日常步骤见 [开发流程](DEVELOPMENT_WORKFLOW.md)。

## 目标与职责

移除可选业务插件后，主程序保留同级 `../srvpro/` 的基础功能与管理 API 安全行为。
在插件、配置或依赖缺失时，无依赖的基础功能应继续工作。

| 层 | 负责 | 不应承担 |
| --- | --- | --- |
| 宿主 | 协议、房间生命周期、通用策略、插件发现/事件/服务、数据库扩展点 | TT 判断、天梯实体、卡组模板、具体页面清单 |
| 插件 | 自有业务、配置、实体、翻译和公共服务契约 | 直接读取另一插件内部文件，向宿主默认配置塞业务字段 |
| 独立服务 | 自有进程、依赖和部署；通过公开接口协作 | 为复用少量代码强行加入游戏进程或直连业务库 |
| 页面插件 | 页面、静态资源、导航、HTTP 适配 | 复制统计算法或绕过服务端权限校验 |

通用缺陷可在宿主修复，并验证普通模式与插件模式；“保持基准”不意味着禁止经确认的通用修复。
插件名称不是源码禁用词：约束的是业务判断和依赖方向，不以全文关键词搜索代替架构判断。

## 插件契约

- 宿主只扫描 `plugins/` 的一级目录；各插件保持平级。
  通过 `plugin.json` 的 `name`、`main`、`dependencies` 声明身份、入口和真实依赖。
  当前加载器没有供插件随意声明的“加载阶段”字段。
- 依赖必须匹配实际调用。无依赖插件失败不应阻断其他插件；依赖方不能在依赖失效后假装功能可用。
- 在数据库连接前执行 `configure` 和 `register`，连接就绪后执行 `init`。
  实体在 `register` 中注册，不能在建立连接后临时补注册。
- 服务经 `api.provide` / `api.get` 公开；消费者不得直接 `require` 其他插件实体、读取其 JSON
  或持有其内部可变状态。插件自身迁移/测试可使用本插件内部实现。
- 事件需明确参数快照、等待顺序、错误处理和是否影响主流程。宿主隔离异常不等于认证通过；
  必须拒绝的业务校验要返回明确拒绝结果。
- 故障日志包含插件名、钩子/事件名和必要的脱敏上下文，便于定位失败边界。
- 翻译由所属插件通过 `registerTranslations` 注册；不能覆盖其他插件或核心同语言同键。
- HTTP 处理器认领请求后必须结束响应并返回 `true`。不能写入一半再交回默认路由。
- 变更公开服务或事件时同时检查调用方；若不能保持兼容，说明迁移顺序与降级行为。

## 目录与配置

最小插件只需要 manifest 和入口；其余目录按实际职责增加：

```text
plugins/<plugin-dir>/
  plugin.json
  index.js
  README.md
  config.default.json   有配置时提供
  entities.js           有自有业务表时提供
  migrations/           有迁移时提供
  web/                  有页面时提供
```

- 本地 `config.json` 不入库；默认配置不含部署凭据。必要凭据缺失时明确报错/降级，
  不以“默认配置能启动”为由伪造凭据或启用不可用功能。
- 新配置说明含义、默认值、边界与是否需要重启。热更新是模块明确支持的能力，不作全局承诺。
- `deck_analysis` 目录对应 manifest ID `deck-classifier`，保留这个既有映射。
- 网页统一位于 `ladder-web/web/`，公开房间与录像插件仅提供 API。
- 模块 README 只记职责、入口、公共边界、不变量和验证；详细配置/运维手册按需链接，
  不强制每个模块创建相同的一套空文档。

## 数据所有权

- `ladder-core` 拥有用户、月记录、Match 与单局事实；统计插件消费这些事实，不拥有它们。
- `ladder-usage-analytics` 拥有八张使用率派生表；迁移脚本目前位于根 `migrations/`，
  文档靠近插件不要求本轮同步移动可执行脚本。
- 每张插件业务表对应唯一 EntitySchema，并由所属插件在连接前注册。
  参数化 UPSERT/聚合 SQL 不代替实体；跨插件通过公开服务获得仓储。
- 生产禁用自动同步表结构。schema 变更同时维护实体、迁移、运行角色权限、验收、
  映射测试及可行的回退/恢复方案。不可逆迁移须明确备份恢复路径。
- 身份、镜像单局与迁移语义见 [数据契约](DATA_MODEL_AND_MIGRATION.md)，不在本文件重复字段清单。

## 验收边界

宿主机制变化覆盖空插件、启用/禁用、缺失依赖、无效配置及故障隔离；
模块变化覆盖自身业务与实际消费者。关键事务不得因录像文件失败丢失比赛结果。
测试和真实客户端验收按 [开发流程](DEVELOPMENT_WORKFLOW.md) 选择，不要求每次文字修改运行全套。
