# Web 页面开发规范与现状清单

> 状态基准：2026-09-15。本文记录 `srvprotianti` 当前八个公开 Web 页面的实际行为，
> 同时作为后续页面开发、接口联调、公共组件抽取和回归验收的基线。
>
> “当前行为”描述现有代码；“开发约定”描述后续修改必须保持或显式迁移的契约。
> 数据统计口径仍以 `WEB_AND_ANALYTICS_SPEC.md` 为准，项目级约束以
> `PROJECT_HANDOFF.md` 为准。

## 1. 实现边界与文件归属

当前页面没有前端框架或打包器，使用原生 HTML/CSS/JavaScript。八个 HTML 和示例卡组统一
位于 `plugins/ladder-web/web/`；公共基础样式和站点外壳组件位于其 `assets/` 子目录。每页仍
保留页面专属的内联样式和业务脚本。

| 页面 | 页面文件 | 页面/接口归属 |
| --- | --- | --- |
| 使用介绍 | `plugins/ladder-web/web/intro.html` | `ladder-web` |
| 房间列表 | `plugins/ladder-web/web/rooms.html` | 页面和路由属于 `ladder-web`，接口由 `public-room-web` 提供 |
| 录像下载 | `plugins/ladder-web/web/replays.html` | 页面和路由属于 `ladder-web`，接口由 `public-replay-web` 提供 |
| 天梯排行 | `plugins/ladder-web/web/ladder.html` | 页面路由和接口属于 `ladder-web`，数据服务属于 `ladder-analytics` |
| 卡组胜率 | `plugins/ladder-web/web/deck-stats.html` | 页面路由和接口属于 `ladder-web`，数据服务属于 `ladder-analytics` |
| 玩家战绩 | `plugins/ladder-web/web/player-stats.html` | 页面路由和接口属于 `ladder-web`，数据服务属于 `ladder-analytics` |
| 卡片/卡组使用率 | `plugins/ladder-web/web/usage-stats.html` | 页面路由和接口属于 `ladder-web`，数据服务属于 `ladder-usage-analytics` |
| 卡组胜率详情 | `plugins/ladder-web/web/deck-detail.html` | 使用率下钻页，数据服务属于 `ladder-usage-analytics` |

页面清单由 `plugins/ladder-web/routes.json` 统一声明。八个页面只有在 `ladder-web` 插件及其
依赖成功加载时才会被公开；不要在 `ygopro-server.js` 中再次硬编码页面路由。

`Content-Type: text/html; charset=utf-8`。

### 2.1 所有页面共用的 URL 参数

| 参数 | 可选值 | 默认值 | 当前行为 |
| --- | --- | --- | --- |
| `L` | `ja`、`en`、`ko`；`zh` 等同于不传 | `zh` | 决定页面语言；切换语言时使用 `history.replaceState` 改写当前 URL，不触发整页跳转 |
| `jp` | 参数存在即可 | 无 | 旧日语入口，兼容读取 |
| `en` | 参数存在即可 | 无 | 旧英语入口，兼容读取 |
| `kr` | 参数存在即可 | 无 | 旧韩语入口，兼容读取 |

解析优先级按当前代码为日语、英语、韩语、中文。例如同时出现多个旧参数时，`jp` 优先。
新链接只应生成规范形式 `?L=ja|en|ko`；中文链接不带语言参数。语言参数会被顶部导航带到
其他页面。

排行榜页另外支持 `type`、`month`、`rankingBasis`，卡组胜率页另外支持 `month`、`metric`；
三张新页面的业务参数见第 13 节。需要分享/恢复的新页面筛选、搜索和页码会写入 URL，但玩家
密码始终只保存在页面内存中。

组件会用 `aria-current=page` 和下划线标记当前页。导航没有 SPA 行为，每次点击都会重新加载

### 3.2 语言菜单

每页右上角都有语言主按钮和中文、日本語、English、한국어四个选项。

语言识别、URL 规范化、菜单 DOM、公共翻译和导航链接均由 `web/assets/site-shell.js` 提供；
各页面通过 `SrvproWeb.init` 注册页面翻译和语言变化回调，不再复制菜单逻辑。

八页浏览器标题和站点顶部标题都随语言切换；四种公共前缀分别为
“游戏王OCG201103天梯服务器”、“遊戯王OCG 201103 ランキングサーバー”、
“Yu-Gi-Oh! OCG 201103 Ladder Server”和“유희왕 OCG 201103 랭킹 서버”。页面名称部分也随
当前语言切换。不得在新页面中重新使用 `SRVPro`，也不得把中文前缀复制到非中文标题。

- 点击语言主按钮：展开或收起菜单。
- 点击语言选项：更新文案、`document.title`、`<html lang>`、当前选项样式和导航链接。
- 点击菜单以外区域：收起菜单。
- 中文使用 `zh-CN`；另外三种语言分别使用 `ja`、`en`、`ko`。
- 翻译键缺失时回退到中文，再缺失时显示键名。
- 切换语言会重新请求房间列表、录像列表或排行榜；卡组胜率页只重新渲染已有数据；介绍页
  不重新请求配置，只重绘静态内容。

### 3.3 视觉与响应式基线

- 深色背景 `#16202b`、内容背景 `#1d2a38`、表头/控件背景 `#243447`、主强调色
  `#7ec4ff` 或 `#2f5c86`。
- 主字体为微软雅黑/苹方一类中文无衬线字体。
- 数据表格单元格不换行；窄屏通过横向滚动查看。
- 多数页面在 `640px` 以下缩小边距、标题、语言按钮和表格间距。
- 页面不会定时自动刷新。动态页只在首次进入、用户操作或 F5 时取新数据。
- 上述基础样式来自 `web/assets/common.css`；页面内不得重新声明 body、导航、语言菜单和通用

## 4. 使用介绍页

### 4.1 地址、参数与数据源

- 标准地址：`/intro.html`
- 页面参数：仅支持第 2.1 节的语言参数。
- 初始化接口：`GET /api/ladder-config?t=<当前毫秒时间戳>`。
- `t` 只用于前端绕过缓存，后端不读取该字段。

`/api/ladder-config` 成功响应：

```json
{
  "rankingBasis": "points"
}
```

`rankingBasis` 可能为 `points`、`wins`、`diff` 或 `winRate`，用于把“天梯当前按什么排序”的

`plugins/ladder-analytics/config.default.json` 和同目录部署用 `config.json`，所以保存配置后无需
重启；已打开的介绍页刷新浏览器即可读取新值。请求失败、JSON 解析失败或字段缺失时按
`points` 展示。

## 5. 房间列表页

### 5.1 地址、参数与接口

- 标准地址：`/rooms.html`
- 别名：`/`、`/dashboard.html`
- 页面参数：仅支持第 2.1 节的语言参数。
- 数据接口：`GET /api/public/rooms?t=<当前毫秒时间戳>`。

成功响应的结构：

```json
{
  "rooms": [
    {
      "roomid": "12345",
      "roomname": "M#示例房",
      "roommode": 1,
      "needpass": "false",
      "users": [
        {
          "id": "-1",
          "name": "player",
          "ip": null,
          "status": null,
          "pos": 0
        }
      ],
      "istart": "wait"
    }
  ]
}
```

字段约定：

- `roomid` 是房间进程 PID 的字符串；仅在房名缺失时作为 `#<roomid>` 的显示后备。
- `roomname` 已在服务端去掉 `$` 后的密码部分。
- `roommode`：`1` 显示 `MATCH`，`2` 显示 `TAG`，其他值显示 `SINGLE`。
- `needpass` 当前是字符串 `"true"|"false"`，页面不展示该字段。
- `users` 只包含已有 `pos` 的客户端（包括可能的 `pos=7` 观察者），按 `pos` 升序；IP 永远
  是 `null`。
- `status` 默认是 `null`。开启 `showPlayerStatus` 后，对局中且非观察者的玩家可能得到
  `{score, lp, cards}`；当前页面仍不展示它。
- `istart` 等待时为 `wait`；进行中为 `Duel:<局数> Turn:<回合>`；换备阶段为
  `Duel:<局数> Siding`。这些状态值直接显示，不做翻译。

未建立、正在删除或已删除的房间不进入响应。处于 BEGIN 阶段且没有有效座位玩家的随机房
也不展示。

### 5.2 展示内容

页首统计：房间总数、对局中房间数、在线玩家数、最近一次成功处理响应的本地时间。

表格列：

1. 房名及“点击复制房间号”按钮。
2. 类型。
3. 模式。
4. 玩家。
5. 状态：等待为 `wait`，对局中显示当前小局与回合，换备时显示当前小局与 `Siding`。

房间类型按 `roomname` 前缀转换：天梯随机比赛、随机单局、随机比赛、随机双打、AI 对战、
比赛房、双打房；不匹配时直接显示原房名。等待中的天梯房隐藏玩家名并显示“等待匹配中”；
其他空房显示“（等待中）”。对局开始后显示实际玩家名。

### 5.3 按钮和状态

| 控件 | 点击结果 |
| --- | --- |
| 手动刷新 | 重新请求公开房间接口并重绘统计及表格 |
| 每行复制按钮 | 通过临时 `input` 复制去密码后的房名，成功/失败均弹窗 |

| 状态 | 呈现 |
| --- | --- |
| 首次加载前 | 四项统计显示 `-`，表格为空；页面初始化会立即发起请求 |
| 有数据 | 显示统计和全部房间行 |
| 无房间 | 统计均为 0（更新时间除外），表格为空，没有“暂无房间”占位行 |
| 等待中 | 状态绿色；天梯等待房隐藏玩家名 |
| 对局中 | 状态黄色，显示如 `Duel:1 Turn:3`，计入“对局中” |
| 换备中 | 状态黄色，显示如 `Duel:1 Siding`，计入“对局中” |
| 网络失败或 JSON 解析失败 | 只把更新时间位置改为“加载失败: <错误>”；已有统计和表格不会主动清空 |
| HTTP 错误但响应仍是 `{error: ...}` JSON | 当前未检查 `response.ok`，会被当作空房间成功处理：统计变为 0、表格清空、更新时间更新 |

## 6. 录像下载页

### 6.1 地址、页面状态与接口参数

- 标准地址：`/replays.html`
- 页面 URL 参数：仅支持第 2.1 节的语言参数。
- 页面内部默认值：`currentPage=1`、`pageSize=20`、空搜索词、全部卡组类型。
- 列表接口：
  `GET /api/public/replays?page=<页码>&pageSize=<每页数>&search=<关键词>&deckTypeId=<卡组类型>&t=<时间戳>`。

接口参数：

| 参数 | 后端规则 |
| --- | --- |
| `page` | 数值，最小 1；非法或缺失时为 1 |
| `pageSize` | 数值，最小 1，最大取插件 `maxPageSize`（默认 100）；非法或缺失时取 `defaultPageSize`（默认 20） |
| `search` | 去首尾空白并转小写，对录像文件名做不区分大小写的包含匹配 |
| `deckTypeId` | 正整数时仅保留至少一方 G1 卡组属于该细分类的天梯录像；缺失、空值或非法值表示不过滤 |
| `t` | 后端忽略，仅用于前端绕过缓存 |

搜索框文案是“按玩家 ID 搜索”，但当前后端实际搜索完整录像文件名。只有文件名包含玩家 ID
时才能命中。

成功响应：

```json
{
  "replays": [
    {
      "name": "2026-09-14 12-00-00 playerA VS playerB.yrp",
      "size": 1024,
      "mtime": "2026-09-14T04:00:00.000Z",
      "duelCount": 1,
      "winner": "playerA",
      "players": [
        {"id": "playerA", "deckbuffer": "<base64 或 null>", "deckTypeId": 1027, "deckNames": {"zh": "六武众"}}
      ]
    }
  ],
  "total": 1,
  "page": 1,
  "pageSize": 20,
  "deckTypeId": 1027,
  "deckTypes": [{"id": 1027, "code": "SIX_SAMURAI", "names": {"zh": "六武众"}}]
}
```

录像目录是权威列表来源，数据库只补充局数、胜者和卡组。数据库关联缺失不会隐藏磁盘文件。
接口按文件名倒序排列；`mtime` 当前不参与页面显示。普通列表只解码当前页至多 20 条录像的
`startDeckBuffer` 并按当前模板识别类型，不扫描全部历史卡组。选择卡组筛选时使用
`LadderMatchGame` 已保存的 G1 类型定位录像，结果缓存 60 秒并在新 Match 提交时清空；不新增
数据表或索引。缺少天梯单局/DuelLog 关联的历史录像在未筛选时仍显示，但不能命中类型筛选。

### 6.2 展示内容

表格列为时间、对战双方、第几小局、胜者、文件大小、录像下载、玩家 1 卡组类型、玩家 2

## 7. 天梯排行页

### 7.1 地址、页面状态与接口参数

- 标准地址：`/ladder.html`
- 页面 URL 参数：除第 2.1 节的语言参数外，支持 `type`、`month`、`rankingBasis`。
- 页面默认值：总战绩、第 1 页、每页 50 人、空搜索词、当前月份、后端默认排序依据。
- 列表接口：
  `GET /api/ladder?type=<类型>&page=<页码>&pageSize=50&search=<关键词>&month=<月份>&rankingBasis=<依据>&t=<时间戳>`。

其中总榜不发送 `month`，初始化第一次请求不发送 `rankingBasis`。

页面访问参数：

| 参数 | 页面规则 |
| --- | --- |
| `type` | `total` 为总战绩，`month` 为月战绩；其他值回退 `total` |
| `month` | 合法格式为 `YYYYMM` 且月份为 `01`～`12`；缺失或非法时使用浏览器当前月份。早于最近 12 月的合法月份会临时加入下拉框 |
| `rankingBasis` | `points`、`wins`、`diff`、`winRate`；缺失或非法时不向列表接口传该字段，由后端实时配置决定 |

用户切换榜单、月份或排序依据时，页面使用 `history.replaceState` 同步这些参数，不触发整页
跳转。未显式传 `rankingBasis` 的页面在每次刷新数据时都继续省略该接口参数，因此修改
`ladder-analytics/config.default.json` 或部署 `config.json` 后，无需重启，页面点击刷新即可
采用新默认排序。用户显式选择或 URL 显式指定的排序依据优先于 JSON 默认值。

| 参数 | 后端规则 |
| --- | --- |
| `type` | 只有 `month` 表示月榜，其他值均回退 `total` |
| `month` | 去除非数字后取前 6 位；不足 6 位时回退服务器当前 `YYYYMM` |
| `rankingBasis` | `points`、`wins`、`diff`、`winRate`；其他值回退插件配置值 |
| `page` | 数值，最小 1，默认 1 |
| `pageSize` | 数值，最小 1，最大默认 100，默认 50 |
| `search` | 去首尾空白并转小写，对规范账户名做不区分大小写的包含匹配 |
| `t` | 后端忽略，仅用于前端绕过缓存 |

成功响应：

```json
{
  "type": "total",
  "month": null,
  "rankingBasis": "points",
  "total": 1,
  "ladder": [
    {
      "name": "DisplayName",
      "wins": 10,
      "losses": 5,
      "duelPoints": 1012,
      "rank": 1,
      "diff": 5
    }
  ]
}
```

月榜响应的 `month` 为规范化后的 `YYYYMM`。`total` 是搜索过滤后的结果数；`rank` 在搜索和
分页前基于完整所选榜单生成，因此搜索结果保留全局真实名次。相同指标按规范账户名升序
打破并列，当前名次是连续序号，不使用并列名次。

## 8. 卡组胜率页

### 8.1 地址、页面状态与接口参数

- 标准地址：`/deck-stats.html`
- 页面 URL 参数：除第 2.1 节的语言参数外，支持 `month`、`metric`。
- 页面默认值：当前月份、第 1 个指标“Match 综合胜率”。
- 数据接口：`GET /api/ladder-deck-stats?month=<YYYYMM>`。

`month` 的后端规范化规则与天梯月榜相同。页面默认列出最近 12 个自然月；URL 指定更早的
合法月份时会额外加入该选项。结果按月份在进程内缓存，默认 TTL 为 45 秒；新 Match 提交后
对应月份缓存失效。

页面访问参数：

| 参数 | 页面规则 |
| --- | --- |
| `month` | 合法格式为 `YYYYMM` 且月份为 `01`～`12`；缺失或非法时使用浏览器当前月份。早于最近 12 月的合法月份会临时加入下拉框 |
| `metric` | 使用下表的稳定指标 ID；缺失或非法时回退 `matchOverall` |

指标 ID 依次为：`matchOverall`、`matchFirst`、`matchSecond`、`gameOverall`、`gameFirst`、
`gameSecond`、`mainOverall`、`mainFirst`、`mainSecond`、`sideOverall`、`sideFirst`、
`sideSecond`。用户修改月份或指标时，页面会把参数同步到 URL；月份仍需点击“刷新”才请求
新数据，指标使用已有数据立即重绘。

成功响应：

```json
{
  "monthKey": "202609",
  "decks": [
    {
      "id": "hero_group",
      "name": {"zh": "英雄", "en": "HERO", "ja": "ヒーロー", "ko": "히어로"},
      "members": [578, 579, 580, 581]
    }
  ],
  "stats": {
    "hero_group::all": {
      "matches": 10,
      "matchWins": 6
    }
  }
}
```

每个统计对象实际包含全部 24 个计数字段：

| 维度 | 总数 | 胜数 |
| --- | --- | --- |
| Match 综合 | `matches` | `matchWins` |
| Match 先攻 | `firstMatches` | `firstWins` |
| Match 后攻 | `secondMatches` | `secondWins` |
| 单局综合 | `games` | `gameWins` |
| 单局先攻 | `firstGames` | `firstGameWins` |
| 单局后攻 | `secondGames` | `secondGameWins` |
| 主牌局综合 | `mainGames` | `mainGameWins` |
| 主牌局先攻 | `mainFirstGames` | `mainFirstGameWins` |
| 主牌局后攻 | `mainSecondGames` | `mainSecondGameWins` |
| 备牌局综合 | `sideGames` | `sideGameWins` |
| 备牌局先攻 | `sideFirstGames` | `sideFirstGameWins` |
| 备牌局后攻 | `sideSecondGames` | `sideSecondGameWins` |

### 8.2 展示内容与方向

当前显示分组已从卡组分类元数据中独立出来，由
`plugins/deck_analysis/deck_display.json` 的 `groups[].isDisplayed` 和 `displayOrder` 决定。
基准状态为 8 组：英雄、代行、齿轮、同调均、暗黑界、六武众、兔 beat、机巧。配置在每次
统计请求时重读；分组内容变化会使旧的月份缓存失效，因此保存后无需重启服务器。完整用法见
`plugins/deck_analysis/DECK_DISPLAY_CONFIG.md`。

- 行是左侧卡组，列是上方对手；单元格键为 `<行组 id>::<列组 id>`。
- 页面提示明确胜率方向为“左侧卡组对阵上方卡组”，并另行说明当前按大类展示、部分数据由
  同一大类下的多个细分类卡组汇总而成。
- 每行末尾“全部”使用 `<行组 id>::all`。
- “全部”的分母包含未展示分类，而不是可见 8 列之和；不能用可见列求和替换。
- 摘要显示“已统计 8 个卡组 / 202609”。这里的数量是展示分组数，不是有样本的分组数。

百分比按 `胜数 / 总数 * 100` 保留两位小数。鼠标悬停在有效百分比上时，自定义 tooltip
显示 `胜数/总数`。50% 使用中性文字色，高于 50% 逐渐变绿，低于 50% 逐渐变红；颜色只作
视觉提示，精确值仍以百分比和 tooltip 为准。颜色函数与详情页统一，0%/50%/100% 分别为
`#ef837f`/`#dce6f0`/`#73d6a3`。

### 8.3 按钮和状态

| 控件 | 点击结果 |
| --- | --- |
| 月份下拉框 | 只改变选择值，不自动请求 |
| 刷新 | 请求所选月份并重绘摘要和矩阵 |
| 12 个指标按钮 | 切换当前统计字段并用已有数据立即重绘，不请求接口 |
| 有效百分比单元格 | 无点击动作；鼠标悬停显示胜数/总数，移出或页面滚动时隐藏 |

12 个指标的顺序与第 8.1 节字段表一致：Match 3 项、全部单局 3 项、主牌局 3 项、备牌局
3 项。

| 状态 | 呈现 |
| --- | --- |
| 初始请求中 | 摘要显示“正在加载”；首次加载时表格为空，刷新已有数据时旧矩阵暂时保留 |
| 正常且有分母 | 显示两位小数百分比、颜色和 tooltip |
| 对应分母为 0 | 显示“数据不足”，不显示百分比和 tooltip |

兼容分组规则的已知问题：未配置 `archetypeIds` 时，`loadDisplayGroups` 依靠卡组 `code` 等于家族代码或以
`<家族代码>_` 开头推导家族成员，且只有 `type=custom` 才应用 `includeBranches`。
`SYNCHRO_SPEED` 会进入“同调均”，`JUNK_DOZER_PLANT` 不会进入。这与元数据中
`includeBranches: [0, 1]` 的产品意图可能不一致。新配置可用明确的
`"archetypeIds": [1026, 1027]` 绕过前缀推导；是否将两者都计入仍需先确认产品口径，不能
通过修改“全部”分母来掩盖差额。

- `common.css` 提供背景、字体、导航、语言菜单、按钮、响应式表格和基础控件；页面内只保留
  专属布局及颜色规则。
- 为兼容当前无需构建的部署方式，组件使用普通浏览器脚本及只读全局对象 `SrvproWeb`，没有
  增加 npm 前端构建链。
- `/assets/` 使用独立安全分支，不复用固定返回 `text/html` 的页面路由。
- 组件向页面公开 `getLanguage`、`t`、`init`；语言变化由 `onLanguageChange` 回调通知页面，
  页面只维护业务刷新或重绘逻辑。

新增页面时应在 `web/` 添加 HTML，在 `routes.json` 注册路由，并在 `site-shell.js` 的
`NAVIGATION`、`NAV_TEXT` 各增加一项；页面通过 `data-site-shell` 和 `SrvproWeb.init` 接入，
不再复制导航或语言菜单。

## 10. 后续开发约定

### 10.1 接口与状态

- 页面使用公开 API，不得改回需要管理员密码的 `/api/getrooms` 或 `/api/replay...`。
- 新增/修改参数时，同时更新本文件的页面 URL、接口参数、默认值、非法值回退和响应示例。
- 新代码必须检查 `response.ok`，并把 HTTP 错误、网络错误、空数据和加载中分开呈现。当前
  部分页面会把 `{error: ...}` 当成空数据，这是待重构行为，不应复制。
- 筛选条件改变后应回到第 1 页；后端返回的规范化页码和 `pageSize` 应成为前端显示依据。
- 需要可分享/可恢复的筛选状态时，应使用 URL 参数并说明兼容策略；不要静默改变现有参数
  含义。
- 动态数据不允许通过拼接不可信字符串写入 `innerHTML`。远端文本使用 `textContent` 或可靠
  转义；介绍页的富文本翻译和本地元数据也应限定为受信源码。

### 10.2 多语言

- 八页继续同时支持中文、日语、英语、韩语；新增可见文案必须一次补齐四种语言。
- 新链接生成规范 `L` 参数，继续读取旧 `jp`/`en`/`kr` 参数，除非提供明确迁移期。
- 错误提示、复制反馈、空状态、tooltip 和无障碍标签都属于可见文案，必须进入翻译表。
- 不要翻译用户 ID、房间名、录像文件名、卡组文件内容或接口枚举原值；需要友好显示时建立
  显式映射并保留原值语义。

### 10.3 隐私与下载安全

- 不向公开页面返回管理员密码、天梯账户密码、真实 IP 或未脱敏房间密码。
- 房间名继续在服务端和前端双重避免显示 `$` 后的密码部分。
- 下载接口只能访问固定根目录内经过 basename/边界校验且扩展名允许的文件。
- 用户名用于文件名时要考虑操作系统非法字符和超长名称；改变既有下载命名规则时必须同步
  更新本文件及 `WEB_AND_ANALYTICS_SPEC.md`。
- 排行榜显示 `displayName`，认证和搜索关联仍使用规范小写 `name`。

### 10.4 可访问性与移动端

- 图标按钮必须有可翻译文本或 `aria-label`；当前活动页、活动 tab 和禁用状态应能被辅助
  技术识别，不能只依赖颜色。
- tooltip 信息还需能通过键盘焦点和触屏获得；胜率高低不能只靠红绿区分。
- 保持窄屏横向表格滚动，并测试 320px 宽度下导航、搜索、分页和语言菜单不遮挡主要操作。
- 动态刷新后应尽量保留合理焦点，错误/空状态可使用适当的 live region 通知。

## 13. 2026-09-15 新增页面契约

以下三页与原五页都位于 `plugins/ladder-web/web/`。公共导航新增“玩家战绩”和“使用率”；
`deck-detail.html` 不单列导航按钮，访问时高亮“使用率”。详细统计定义、认证边界和数据模型见
`LADDER_PLAYER_AND_USAGE_SPEC.md`。

### 13.1 玩家战绩 `/player-stats.html`

页面 GET 参数为 `player`（精确 ID）、`month=YYYYMM`、`page` 和公共语言参数 `L`；密码禁止
进入 URL。搜索框接受 `id` 或 `id$password`，拆分后只把 ID 写回 URL，密码仅留在页面变量中。

- “查询”解析搜索框并回到第 1 页；“刷新”以当前内存中的密码重新请求；月份变化后回到第 1 页。
- 数据接口为 `POST /api/ladder/player`，JSON 字段为 `player/password/month/page`；响应设置
  `Cache-Control: no-store`。
- 上板块展示总/月积分、胜负、胜负差、胜率，以及全时期最近 10 场（不足则按实际场数）的
  SVG 积分折线。折线包含首场赛前基线和每场赛后积分。“所选月战绩”与折线标题分别使用
  独立的上边距，不再受卡片通用标题零边距影响。
- 总/月摘要的胜场固定为绿色、负场固定为红色、胜负差按正绿/负红/零中性色，胜率复用全站
  以 50% 为中点的动态红绿梯度。
- 下板块每条显示猜拳、G1 先攻、胜负、由单局计算的比分、双方积分变化、双方变化后积分、
  双方细分类卡组、对手和结算时间。可识别且不是“其他”的双方卡组名均为链接，点击进入
  `/deck-detail.html` 并携带细分类 ID、当前月份、月度时期和语言。认证模式每页 20 条、所选月全部记录；公开模式仅当前月最近 10 条，选择
  其他月为空，并弹出四语言公开模式 toast。
- 记录中的结果按胜绿/负红显示，双方积分变化均按正绿/负红/零中性色显示；点击对手 ID 会清除
  当前内存密码，在本页切换为该对手并立即查询，月份保持不变、页码回到 1。
- 双方下载按钮调用 `POST /api/ladder/player/deck`，字段为
  `player/password/matchId/side=player|opponent`。公开模式仅能下载其当前月可见最近 10 场，
  认证模式每次重新认证；初始卡组、比分或其他信息缺失时显示横杠。
- 页面底部常驻四语言模式说明：公开模式只输入玩家 ID，显示总/月摘要、全时期最近 10 场曲线、
  当前月最近 10 条记录并允许下载这些可见记录的双方初始卡组；带密码模式输入
  `玩家ID$密码`，可分页查看所选月全部记录并下载初始卡组。说明同时强调密码只放在请求体和
  当前页面内存中，不进入 URL。

状态包括：初始空白、玩家不存在、加载失败、公开降级、有摘要但无可见记录、分页记录、单个
卡组可下载/不可下载。

### 13.2 卡片/卡组使用率 `/usage-stats.html`

GET 参数为 `metric=monster|spell|trap|extra|side|deck`、
`period=today|week|month|all`、`month=YYYYMM`、`page`、`L`。按钮组切换六种指标和四种时期；
仅 `period=month` 显示月份选择器，任何筛选变化回到第 1 页。

- 卡片调用 `GET /api/ladder/usage/cards`。只返回使用率前 200，50 条分页；列为排名、可跳转
  `ygocdb.com/card/<密码>` 的密码和名称、采用卡组数、使用率、投入 1/2/3 张的卡组数。
- `monster/spell/trap` 只读主卡组相应类型，`extra` 只读额外，`side` 只读副卡组。异画按
  alias 归并；卡片分母是有效解码的初始卡组数。
- 卡组调用 `GET /api/ladder/usage/decks`，展示所有细分类、使用数和使用率。“其他”(4095)
  始终最后且不可点击，其余名称进入详情页并携带当前时期和月份。
- 细分类四语言名称读取 `deck_analysis.json`，大类名称读取 `deck_display.json`。英文名称按本
  环境固定口径展示，例如 `Asceticism Six Samurai` / `Non-Asceticism Six Samurai`、
  `Dino Rabbit`、`Plant Synchro`、`Quickdraw Junk Doppel`、`Gadget`、`FTK Dark World`、
  `Blackwing`、`Vayu`、`Gravekeeper`、`Alive Hero`、`Frog Monarch`、`Breaker Hero` 和
  `Lightsworn`；修改细分类名称时必须同步检查介绍页 `example-decks.json` 中对应示例卡组。
- 页面始终展示 `validCardDecks / allDecks` 快照覆盖率；无数据、接口错误和零分母均不得显示
  `NaN` 或无穷值。

### 13.3 卡组胜率详情 `/deck-detail.html`

GET 参数为 `deckTypeId`、`q`、`period`、`month`、`L`。无 ID 且搜索框为空时保持空白；`q`
在四语言名称、代码和数字 ID 中模糊匹配，多个候选通过按钮让用户选择，稳定 ID 优先于名称。
“其他”不提供详情。

接口为 `GET /api/ladder/deck-detail`。标题下展示该时期卡组使用率和样本数；Match、全部单局、
主牌局、备牌局四个 tab 各列综合/先攻/后攻，共 12 个指标。每个有样本的单元格固定两行展示
两位小数胜率与 `胜场 / 样本`，无样本显示横杠；第一行是对阵全部卡组总计，其后按对局样本
排列具体细分类对手，“其他”(4095) 无论样本数多少都固定在最后一行。除“其他”外的对手
卡组名均可点击；点击后保留时期、月份和语言参数，在当前页重新加载该卡组的数据。

胜率色值复用 `site-shell.js` 的动态梯度：50% 为 `#dce6f0`，0%/100% 的端点分别为
`#ef837f`/`#73d6a3`，中间按离 50% 的距离线性增强；`deck-stats.html` 使用完全相同的函数和
端点。若所选细分类存在数字 `.ydk` 模板，标题下显示“包含模板文件全部卡片的卡组会被识别为
本类型”，其中“模板文件”请求
`GET /api/ladder/deck-template?deckTypeId=<ID>` 下载实际用于分类的模板。服务端只从启动时已加载
的数字模板清单按 ID 取文件，不接受文件路径；无对应模板返回 404。
