# SRVPro 天梯版新增功能与耦合清单

## 1. 审计范围

基准目录：`F:\MyCardLibrary\srvpro\srvpro`

天梯目录：`F:\MyCardLibrary\srvpro\srvprotianti`

排除项：`ygopro/`、`srvpro.dump`、`SimpleMonitor.ps1`。运行产生的录像和日志只用于识别目录用途，不作为源代码差异。

## 2. 当前新增能力

### TT 天梯随机模式

- 将 `TT` 识别为双人 Match 随机模式。
- 使用 `M#` 房名前缀生成 Match 房间。
- 使用 `用户名$密码` 登录，未注册用户在结算时注册。
- 已注册用户校验天梯密码。
- 开局前隐藏对手名称。
- 进入房间时展示当月等级分、胜场和胜率。
- 具体房名只允许在开局后用于观战。
- 当前实现对断线房、重复 IP 对手和受限制玩家分池存在 TT 特例。

### 天梯计分和排行

- 总胜负、月胜负、总等级分和月等级分。
- 初始等级分 1000。
- Elo 风格动态分差，支持 `K`、最小变化值和最大变化值。
- 可按等级分、胜负差或胜率排序。
- 总榜、月份榜、搜索和分页。

### 数据库数据

- `ladder_user`
- `ladder_month_record`
- `ladder_match`
- `ladder_match_game`

当前通过 TypeORM 实体通配符和 `synchronize: true` 加载，没有插件级正式迁移流程。

### 卡组分类

- 读取数字命名的 YDK 模板。
- 模板文件名作为卡组类型 ID。
- 当前实现只比较模板主卡组，且在无法完整匹配时会返回重合最多的模板。
- 卡组元数据定义家族、分支、强度和前端展示分组。

### Web 与公开接口

- 使用介绍、房间列表、录像列表、天梯排行、卡组胜率页面。
- 中、日、英、韩四语言切换。
- 示例卡组下载。
- 排行榜、录像和房间搜索/分页。
- 录像关联双方卡组下载。
- 新增天梯与卡组统计 API。
- 当前实现直接放宽了原 `/api/getrooms` 和 `/api/replay` 的鉴权。

### PostgreSQL 与部署调整

- 新增 `pg` 驱动。
- 数据库日期、主键、小整数和清表 SQL 的 PostgreSQL 适配。
- 支持 PostgreSQL、MySQL、SQLite 和 sql.js 分支。
- 最大内存阈值改为读取配置。
- Lite 镜像增加 YGOPro 线程栈设置和验证。

## 3. 当前耦合位置

- `ygopro-server.js`：TT 匹配、认证、隐藏名称、单局/Match 时序、录像保存、HTTP API 和静态页面。
- `ygopro-server.coffee`：只有部分 TT 行为，和生成的 JS 严重不同步。
- `data-manager/DataManager.ts` 与 `.js`：天梯实体访问、计分、卡组分类、统计和排行。
- `data-manager/entities/`：天梯实体与 PostgreSQL 类型兼容混在主实体目录。
- `web/`：新增页面位于主项目目录。
- `plugins/`：目前只有配置、模板和元数据，没有被现行插件加载器执行的入口。

## 4. 删除当前 plugins 后的实际结果

删除插件目录内容并不会删除天梯功能：

- TT 仍被主程序识别。
- 天梯认证和结算仍运行。
- 天梯实体仍注册。
- 天梯和 Web 路由仍存在。
- 计分改用主代码硬编码默认值。
- 卡组识别统一回退为其他卡组。
- 卡组统计元数据加载失败并返回空结果。

因此当前结构不符合插件化目标。

## 5. 与基准行为无关但必须恢复的差异

- 天梯版本缺少基准项目的 `duel-finalization` 模块和测试。
- 大量编译产物与源文件不同步。
- 原录像保存范围被改成主要只保存 TT，而不是基准逻辑。
- 原录像下载鉴权被直接移除。
- 原房间查询鉴权流程被直接修改。

这些内容应先恢复为基准行为，再由插件通过通用钩子增加能力。
